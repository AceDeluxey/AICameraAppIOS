## 1. 产品结论

AICameraApp iOS 是一款面向观鸟爱好者、长焦拍鸟用户和手机接望远镜用户的 AI 相机。它不以“能识别多少种鸟”为第一卖点，而是解决系统相机在拍鸟时最直接的问题：目标小、遮挡多、容易跑焦、长焦抖动大、鸟随时会飞走。

首版必须打通以下闭环：

**发现鸟 → 稳定确认整鸟目标 → 自动把焦点落到整鸟区域 → 长焦稳定取景 → 快速完成拍摄。**

鸟种识别是增强价值，不得拖慢取景、对焦和拍摄主链路。

## 2. 目标与非目标

### 2.1 产品目标

- 在复杂枝叶背景中，比系统相机更快把焦点落到鸟主体上。
- 鸟移动或被短暂遮挡时，焦点不频繁跳回背景。
- 在 3×、5× 等长焦以及外接望远镜场景中，提供可感知的取景稳定提升。
- 与 Android 版保持统一的产品结构、配色、控件位置和术语，降低双端维护成本。
- 所有 AI 推理默认在本机完成，离线可用，不上传照片和视频。

### 2.2 商业目标

- 验证小众摄影工具的付费意愿与留存，而非追求大众相机规模。
- 首版预留一次性买断或 Pro 内购能力；正式定价在小规模测试后确定。
- 核心付费价值应来自更高出片率，而不是单纯解锁鸟种数据库。

### 2.3 本期非目标

- 社区、作品流、关注和聊天。
- 云端图库、跨设备同步和云端 AI 推理。
- 完整替代系统专业相机或第三方视频电影机。
- 自研 RAW 处理、HDR 合成和大型后期编辑器。
- 首版覆盖所有 iPhone；无长焦机型保留基础能力，但不是核心验收机型。

## 3. 用户与场景

### 3.1 核心用户

1. 使用 iPhone Pro 长焦拍鸟的观鸟爱好者。
2. 使用手机夹具连接单筒/双筒望远镜记录鸟类的用户。
3. 不熟悉专业相机参数，但希望快速拍清鸟的新手。

### 3.2 关键场景

- 林地枝叶间发现小型鸟，背景纹理复杂，系统对焦容易落到树枝。
- 水面或天空中的鸟持续移动，需要稳定跟踪并快速抓拍。
- 使用长焦或外接望远镜时轻微手抖被放大，需要稳定预览和录制。
- 弱光、逆光或鸟体只占画面很小比例时，需要明确显示识别状态而不阻塞快门。

## 4. 产品范围与优先级

### P0：真机技术验证

- AVFoundation 相机预览、拍照和用于防抖对照的视频录制。
- 枚举当前设备可用摄像头、格式、帧率和防抖模式。
- 实时鸟体检测，输出检测框、置信度和推理耗时。
- 选择最高置信度整鸟目标并稳定输出目标框。
- 将整鸟区域中心映射为相机对焦点，验证连续检测时的对焦行为。
- 系统防抖关闭/支持模式的对照录制。
- 比较模型转 Core ML 与 iOS ONNX Runtime 两条路线的速度、准确率、包体和内存。

P0 是是否进入完整开发的门槛，不要求完整 UI。

### P1：可用 MVP

- 拍照模式：预览、快门、相册入口、4:3/16:9 比例切换。
- 鸟模式：开关、整鸟检测框、目标保持、自动整鸟区域对焦。
- 镜头选择：按设备真实能力展示，例如 0.5×、1×、3×、5×；选定后不得因数字变焦自动跳到其他物理镜头。
- 连续变焦：滑杆与双指缩放联动。
- 拍照保存到系统照片，保留方向、时间和允许情况下的位置元数据。
- 权限拒绝、相机占用、过热、模型加载失败等可恢复状态。

### P2：增强 MVP

- 鸟种 Top 3 候选、概率和中文名称。
- GPS 分省分月地理先验；定位不可用时自动退化为纯模型结果。
- 视频模式、同期声、全像素/4K/1080p/720p 与 30/60/120fps 选择；仅显示设备实际支持的组合。录制中默认暂停鸟类 AI 分析，与 Android 行为一致。
- 网格、录制时长、电量和剩余空间 HUD。
- Auto/Pro 切换及设备支持范围内的曝光、ISO、快门、对焦控制。

### P3：差异化增强

- 系统支持的标准、电影效果、低延迟等模式对照。
- 针对长焦取景优化稳定策略，并量化画面裁切与延迟。
- 评估 Core Motion 陀螺仪数据与视频帧时间戳对齐。
- 仅当系统方案不足且收益通过盲测后，再进入自定义实时或录后防抖开发。
- 鸟头/鸟眼精确定位、多鸟选择和视频录制中 AI 分析均作为增强实验，不作为首版发布门槛。

## 6. 核心交互

### 6.1 默认拍摄

1. 打开 App，进入全屏黑底取景。
2. 默认 Auto、拍照模式、1× 镜头；鸟模式沿用用户上次状态。
3. 用户开启鸟模式后，检测在后台持续运行，快门始终可用。
4. 检测到鸟时显示橙色整鸟框，并以最高置信度目标的整鸟区域作为自动对焦目标。
5. 达到对焦触发条件后更新相机兴趣点；同一目标持续跟踪时限制重复对焦频率，避免抽动。
6. 用户点击快门后立即拍摄，不等待分类结果。

### 6.2 目标选择与丢失

- 单只鸟：使用该鸟作为自动对焦目标。
- 多只鸟：与 Android 一致，首版仅选择最高置信度目标，不提供点选切换。
- 短暂漏检：在有限时间内保留当前目标状态，不立刻跳回背景。
- 超时丢失：回到常规连续自动对焦，并隐藏对焦框。
- 用户点按画面：人工对焦优先，短时间暂停 AI 抢焦。

### 6.3 防抖

- 用户不需要理解 EIS/OIS 名称；界面只展示“稳定：自动/关闭”，高级诊断页可显示实际模式。
- 切换镜头、格式或帧率后重新检测支持能力。
- 防抖导致裁切、延迟或不支持时，界面不得继续显示为已启用。
- **预览稳定**：衡量长焦取景时主体位移、画面裁切和显示延迟，目标是让用户更容易构图和对焦。
- **照片出片**：衡量同场景照片清晰率；若系统拍照链路不可直接控制防抖，不得把预览变稳宣传为照片防抖增强。
- **视频稳定**：通过关闭/系统自动/设备支持模式的同条件录制对照，分别验收抖动、裁切、果冻效应和延迟。

## 7. 视觉与设计规范

### 7.1 设计语言

整体保持 Android 版的“黑色相机取景器 + 暖橙操作强调”风格：画面优先、信息克制、户外强光下可读。

| Token | 数值 | 用途 |
| --- | --- | --- |
| `background` | `#000000` | 全屏底色 |
| `accent` | `#FF8C4B` | 快门、选中态、变焦滑块、鸟目标框 |
| `controlFill` | `#4A403A` | 圆形按钮和胶囊底色 |
| `primaryText` | `#FFFFFF` | 主文字和图标 |
| `secondaryText` | `#B0B0B0` | 未选中或次级信息 |
| `recording` | `#FF5555` | 录制状态 |
| `textShadow` | `#99000000` | 亮背景可读性 |

### 7.2 页面布局

- 全屏相机预览，根背景为纯黑。
- 左上：照片比例；视频模式显示规格入口。
- 右上：构图线入口，按无、三分、黄金、十字、对角线循环。
- 顶部居中：鸟种 Top 3 或录制 HUD，两者不得重叠。
- 底部第一层：Auto/Pro、可用镜头倍率、拍照/视频胶囊。
- 底部第二层：左侧相册、中央 76pt 快门、右侧鸟模式或 FPS。
- 变焦滑杆悬浮在底部控制区上方。

### 7.3 控件规则

- 视觉尺寸与 Android 基本一致，但可点击区域不得小于 44×44pt。
- 快门为暖橙实心圆、4pt 白色描边；录像中变为红色录制态。
- 普通圆形按钮使用深棕灰底；选中胶囊使用暖橙底和黑字。
- 鸟种结果使用白色粗体、细黑描边、最多三行，不放大面积遮挡主体。
- 必须适配安全区域、横竖屏策略和不同屏幕尺寸，不直接照搬 Android dp 坐标。
- 支持 VoiceOver 标签、动态字体的合理上限和足够对比度。

## 8. AI 与相机策略

### 8.1 实时管线

1. 相机帧进入轻量检测器，帧率与分辨率按设备性能动态降级。
2. 跟踪器在检测间隔内维护目标，避免每帧都做完整推理。
3. 选择最高置信度整鸟框，并通过时域确认和框平滑减少偶发误检与位置抖动。
4. 坐标经过预览裁切、旋转和镜像变换后映射到相机对焦点。
5. 鸟种分类在低优先级队列执行，不阻塞预览、对焦和快门。

### 8.2 对焦保护

- 设置置信度、稳定帧数、最短重触发间隔和位移阈值。
- 聚焦期间避免因检测框轻微抖动重复下发对焦命令。
- AI 对焦失败或硬件不支持时回退到系统连续自动对焦。
- 记录“检测到目标、发出对焦、相机报告完成、目标丢失”时间点，供真机分析。
- 鸟头/鸟眼精确定位不属于首版承诺，仅在整鸟对焦稳定后作为独立实验评估。

### 8.3 模型复用验收

- 使用同一验证集比较 Android 原模型与 iOS 路线。
- 分类 Top-1/Top-3、检测召回率和误报率的差异必须可量化。
- 模型转换若造成明显精度下降，不为追求纯 Core ML 强行转换。
- 模型、标签和地理数据需记录来源、版本、许可证与校验值。

## 9. 性能、隐私与稳定性

### 9.1 建议验收指标

| 指标 | P0 门槛 | MVP 目标 |
| --- | --- | --- |
| 检测结果延迟 | ≤250ms | 典型场景 ≤150ms |
| 预览流畅度 | 不持续卡顿 | 主流测试机稳定 ≥30fps |
| 主目标保持 | 可完成演示 | 标准样本保持率 ≥80% |
| 拍摄响应 | 不等待分类 | 点击后无可感知 AI 阻塞 |
| 连续运行 | 10 分钟不崩溃 | 20 分钟无严重降频或内存增长 |
| 模型加载失败 | 有明确降级 | 相机基础拍摄仍可用 |

这些指标是首轮工程目标，需根据测试机和实测基线修订。

### 9.2 隐私

- 相机、麦克风、定位、照片权限按功能触发，不在首次启动集中索取。
- 默认不上传原始照片、视频、位置或识别记录。
- 若未来增加诊断上报，必须单独征得同意，并允许关闭。
- 定位只用于照片元数据与地理先验；关闭定位不影响基础拍摄和纯模型识别。

### 9.3 异常与降级

- 无鸟模型：退化为普通相机并提示一次。
- 无定位：禁用地理先验，不伪造地区。
- 无长焦：按实际镜头展示倍率。
- 防抖模式不支持：自动选择受支持模式或关闭。
- 温度或内存压力过高：降低分析频率，优先保证预览和拍摄。

## 10. 真机测试方案

### 10.1 测试矩阵

- 至少一台带长焦的 iPhone Pro 作为核心机型。
- 至少一台无长焦或较旧机型验证降级行为。
- 场景包含晴天、阴天、弱光、逆光、天空、水面和复杂枝叶。
- 目标包含静止、跳跃、横向飞行、局部遮挡和多鸟同框。
- 每个关键场景与系统相机、Android 版分别录制对照样本。

### 10.2 防抖对照

- 固定镜头、倍率、分辨率、帧率和拍摄时长。
- 分别测试关闭、系统自动、各支持模式和自定义方案。
- 预览测试记录主体位移、裁切比例和显示延迟。
- 照片测试记录同条件多次拍摄的清晰成片率。
- 视频测试记录抖动幅度、裁切比例、果冻效应、画质、延迟和功耗。
- 使用盲测判断“更稳”是否肉眼可感，不只看算法数值。

### 10.3 发布前阻断项

- 鸟框位置与实际目标明显错位。
- AI 连续抢夺人工对焦或频繁抽焦。
- UI 显示防抖开启但实际连接未启用。
- 快门受分类任务阻塞。
- 录制文件损坏、方向错误、无声或无法进入系统照片。
- 权限拒绝后反复弹窗或无法恢复。

## 11. 技术结构建议

建议使用 Swift，界面可采用 SwiftUI 承载状态与面板，相机预览和高频覆盖层按性能需要桥接 UIKit/Metal。模块边界如下：

- `CameraCore`：会话、镜头、格式、照片、视频和权限。
- `BirdDetection`：检测模型、帧调度和性能降级。
- `BirdTracking`：主目标时域确认、框平滑和短时丢失恢复。
- `BirdFocus`：坐标变换、对焦节流和人工优先规则。
- `BirdClassification`：分类、标签和地理先验。
- `Stabilization`：能力探测、系统模式和后续陀螺仪方案。
- `CameraUI`：取景器、覆盖层、控制面板与无障碍。
- `Diagnostics`：帧率、推理耗时、对焦事件、温度和错误日志。

禁止把相机会话、AI、坐标映射和全部 UI 状态集中在单个 ViewController，以避免复制 Android 当前主 Activity 过大的维护问题。

## 12. 里程碑

### M0：项目骨架

- Xcode 工程、签名配置说明、权限文案、基础相机预览。
- 建立模块边界、测试 Target、SwiftLint/格式化与 CI 构建。

### M1：三项核心技术验证

- 鸟体检测性能报告。
- 整鸟目标保持与自动对焦演示。
- 长焦预览、照片清晰率和视频防抖对照结论。

完成标准：三项均在真机可重复演示，且没有发现平台级不可行因素。

### M2：拍照 MVP

- 完成 P1 范围、统一视觉、照片保存和异常降级。
- 至少两台真机完成核心测试矩阵。

### M3：识别与视频

- 完成 P2 范围、模型一致性验证和视频稳定性测试。

### M4：小规模测试

- 通过 TestFlight 邀请观鸟用户测试。
- 以“对焦成功率、实际出片率、次周继续使用、付费意向”决定后续投入。
