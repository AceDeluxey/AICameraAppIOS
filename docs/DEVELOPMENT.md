# AICameraApp iOS 开发协作规则

> 生效日期：2026-08-31
> 默认分支：`main`
> 远程仓库：`https://github.com/AceDeluxey/AICameraAppIOS.git`

## 1. 参考工程与资产

- Android 原始压缩包：`/home/ubuntu/birdCamera/AICameraApp.rar`。它只用于来源追溯，不直接执行、不在压缩包内修改。
- Android 已解压工程：`/home/ubuntu/AICameraApp`。它是 iOS 需求、交互、视觉、算法和模型迁移的对照基线。
- iOS 工程：`/home/ubuntu/AICameraApp-iOS`。所有 iOS 代码、文档和提交都在此仓库完成。
- 不把 Android 构建产物、模型副本或大体积数据直接提交到 iOS 仓库；引入前先确认许可证、商业复用授权和仓库体积方案。
- 密钥、Token、证书、Provisioning Profile、用户照片和精确位置数据不得提交到 Git。

## 2. 阶段性提交

- 每完成一个边界清晰、可独立验收的阶段，先执行与风险相称的检查，再单独提交。
- 提交前检查工作区，只暂存本阶段相关文件，不混入 Owner 或其他任务的改动。
- 提交信息说明成果，避免使用 `update`、`fix` 等无法追溯范围的描述。
- 验证未通过、阶段尚不完整或改动无法安全拆分时，不创建阶段提交，并明确记录原因。
- 文档阶段至少检查链接、路径和 Git diff；代码阶段按项目能力执行格式检查、静态检查、单元测试和构建。
- iOS 相机、对焦、防抖、性能和签名结果必须在 Mac/Xcode 与真机上最终验收；Linux 侧检查不能替代该验收。

## 3. 自动 Pull / Push 流程

Owner 已授权阶段提交完成后自动同步远程仓库，无需每次另行确认。默认流程为：

1. 开始工作前确认当前分支和工作区，执行 `git pull --ff-only origin main`。
2. 完成阶段改动并通过验证后，创建只包含本阶段内容的本地提交。
3. 提交后再次获取远程状态；远端没有新提交时直接执行 `git push origin main`。
4. 远端已有新提交时，在工作区干净的前提下执行 `git pull --rebase origin main`，重新运行必要验证，再执行 `git push origin main`。
5. 出现冲突、非快进拒绝、认证失败、网络失败或不明远端改动时立即停止自动同步并报告，不强推、不覆盖、不自动解决语义冲突。

以下情况禁止自动推送：

- 测试或构建失败；
- 提交包含凭据、签名材料、用户数据或来源/授权不明的资产；
- 工作区混入无法安全拆分的其他改动；
- 需要使用 `--force` 才能推送；
- 仓库或 Owner 明确要求暂不推送。

## 4. 文档与任务状态

- 需求范围变化时同步更新 `docs/PRD.md`。
- 阶段状态和验收结果变化时同步更新 `docs/TASKLIST.md`。
- 影响后续开发的工程约定变化时同步更新本文档。
- 阶段报告、PRD、TaskList 和可交付安装包按需发布到 Agent 文件台。
